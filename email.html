Implementation summary

  • Async job submission — POST /jobs returns immediately (HTTP 202) with a job ID. Supports priority, configurable retries, and per-attempt timeout.
  • Worker execution — Workers claim jobs using PostgreSQL SKIP LOCKED for safe concurrent access. Failed jobs retry with exponential backoff; exhausted jobs move to a dead-letter queue.
  • Full lifecycle visibility — Job status, attempt count, result payload, and per-attempt execution history are all queryable via REST.
  • Queue controls — Queue depth endpoint, drain/resume, and cancel-pending for operational control.
  • Cron scheduling — Recurring jobs via six-field cron expressions with timezone support, plus one-time delayed execution.
  • Observability — Prometheus metrics for queue depth, worker utilization, latency percentiles (p50/p95), and dead-letter rate.
  • Testing — 33 tests (unit + integration with Testcontainers/PostgreSQL) covering concurrent claiming, retry flows, lease recovery, scheduling, and more.
  • CI/CD — GitHub Actions pipeline runs the full test suite on every push — currently passing.
  • Architecture — Diagrams, data model, and at-least-once delivery semantics documented in docs/architecture.md.

Deployment

The service runs on DigitalOcean App Platform as three independently scalable components (API, Worker, Scheduler) backed by managed PostgreSQL. Workers scale independently without affecting the API tier.

Tech stack: Java 21, Spring Boot 3.5, PostgreSQL 16, Docker, GitHub Actions
